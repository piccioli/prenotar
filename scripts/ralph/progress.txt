## Codebase Patterns
- `database/factories/PrenotazioneFactory.php` (and Eloquent factories in general) run under `Model::unguarded()`, so the `definition()` array bypasses `$fillable` entirely and is inserted raw. Dropping/renaming a DB column requires updating every factory that sets it directly, even though normal mass-assignment (`Model::create()`) would silently ignore an unfillable key with no error.
- When removing a DB column that a Filament Infolist/Form still binds via `TextEntry::make('col')->visible(fn (Model $r) => $r->col === Enum::X)`, Larastan (property.notFound) catches property-access closures immediately even though `TextEntry::make('col')` by itself (string key, no property access) does not - property-access closures referencing dropped columns are the first thing to break statically.
- Full QA loop for this project: `./vendor/bin/sail composer qa` (Pint + Larastan level 6 + Pest). Pest here uses a real MariaDB `testing` DB via `RefreshDatabase`, so schema changes are exercised for real, not mocked.
- `tests/Unit/*` do NOT boot the Laravel app (`tests/Pest.php` only does `uses(TestCase::class, RefreshDatabase::class)->in('Feature')`, `phpunit.xml` bootstraps just `vendor/autoload.php`). Calling `app(SomeClass::class)` in a Unit test for a class the container can't trivially build (e.g. a `spatie/laravel-settings` class, whose `default_repository` is `database`) throws `Target class [config] does not exist` because the base `Container` has no Laravel bindings. Fix without pulling in DB/full boot: `app()->instance(SomeClass::class, (new ReflectionClass(SomeClass::class))->newInstanceWithoutConstructor())` then set its public typed properties directly (bypasses the class's own constructor/lazy-load `__get`/`__set` magic entirely) - the plain `Container::instance()`/`::make()` short-circuit works even without Laravel bootstrapped.
- To unit-test code that receives Filament's `Filament\Forms\Set`/`Filament\Forms\Get` (concrete classes, not interfaces, required for Filament's closure DI to inject them), `Mockery::mock(Forms\Set::class)`/`Mockery::mock(Forms\Get::class)` works (neither class is `final`) with `shouldReceive('__invoke')->andReturnUsing(...)` writing/reading a shared array captured by reference - no real Livewire component needed.
- Standalone `Forms\Components\Actions::make([Forms\Components\Actions\Action::make('name')->...])` (a button not tied to any field) gets a default Livewire test component key of `"{$name}Action"` (no leading dot/prefix) when placed directly in a top-level form/wizard-step schema - same pattern already used in this file for `invia_richiesta`/`elimina_bozza` (`app/Filament/Sezione/Resources/PrenotazioneResource.php`), confirmed by running the actual test suite rather than deriving it from `ComponentContainer`/`ActionContainer` source.
- Filament's `ComponentContainer::getComponent($key)` (used internally by `mountFormComponentAction`, `getMountedFormComponentActionComponent`, and all `assertFormComponentAction*` test helpers) defaults `$withHidden` to `false`, i.e. it filters out any component whose `->visible()` closure returns false **before** even trying to match the key. Practical consequence: an Action hidden via `->visible(fn () => app()->environment('local'))` is not just hidden in the UI, it is entirely absent from the schema tree when the closure is false - `assertFormComponentActionHidden()`/`assertFormComponentActionDoesNotExist()` themselves crash (`Call to a member function getKey() on null`) because their error-message string interpolates `$component->getKey()` unconditionally, even when the assertion would otherwise pass. There is no working Filament test helper for "assert this env-gated action doesn't exist" - the practical test is `assertDontSee('<label>')` for the UI + a forced `->call('mountFormComponentAction', $key, $name)->assertStatus(200)` (silent no-op, not 404) to prove it has no effect.
- Consequence of the point above: an `abort_unless(app()->environment('local'), 404)` placed as the first line inside a form Action's `->action()` closure can **never** actually fire via a real Livewire request when that same Action also has `->visible(fn () => app()->environment('local'))`, because both checks read the exact same live environment value in the same PHP process/request - if `visible()` is false the framework already filtered the action out of the tree before the closure could run, and if it's true the abort_unless trivially passes. It's still correct defense-in-depth to keep it (protects against a future Filament refactor or an alternate invocation path), but to actually exercise that specific line in a test you must bypass Filament's mounting layer entirely: reflectively call the private static factory method that builds the `Actions`/`Action` pair, pull the raw `Action` back out via its public `getAction($name)` (from `Filament\Actions\Concerns\InteractsWithActions`, `getChildComponents()[0]` gives the `ActionContainer`), grab the closure with `->getActionFunction()`, and invoke it directly with mocked `Set`/`Get` - see `tests/Feature/Sezione/PrenotazioneWizardAutofillTest.php`.
- To force `app()->environment('local')` to be true/false in a test (e.g. to test a dev-only feature gated by `APP_ENV`), just do `app()->instance('env', 'local')` - Laravel's `Application::environment()` reads the container-bound `'env'` key directly, no need to touch `config('app.env')` or `.env.testing`.
