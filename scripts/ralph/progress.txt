## Codebase Patterns
- Wizard steps for the /sezione Prenotazione resource live in `PrenotazioneResource::wizardSteps()` (app/Filament/Sezione/Resources/PrenotazioneResource.php); the outer `Wizard::make(...)` + nextAction()/skippable() config lives separately in `CreatePrenotazione::form()`, and both must be kept in sync when a step gates progression (nextAction's `->disabled()` closure receives `Forms\Get $get` and is evaluated with the whole live form state, so a condition defined for one step's field also protects later steps for free).
- Custom-styled Filament fields (checkbox with link/warning, radio cards, etc.) use `->view('filament.sezione.forms.components.<name>')` + `->viewData([...])` pointing at a blade partial under `resources/views/filament/sezione/forms/components/`; see `manuale-istruzioni-step.blade.php` / `torre-radio-cards.blade.php` for the pattern (uses `<x-dynamic-component :component="$getFieldWrapperView()" :field="$field">`, `$getState()`, `$getStatePath()`, `x-filament::input.checkbox`).
- `Torre::manuale_pdf_path` sits on the default `public` disk; consumers build the URL manually with `asset('storage/'.$path)`, not `Storage::url()`.
- Feature tests that fill the CreatePrenotazione wizard via `Livewire::test(CreatePrenotazione::class)->fillForm([...])->call('create')` must also `->set('data.manuale_step_confermato', true)` (added in US-001) or they'll fail with a new `accepted` validation error — this affected two test files (`PrenotazioneManualeLettoTest.php`, `PrenotazioneTipoMezzoValidationTest.php`) that had nothing to do with the manuale feature. Grep `CreatePrenotazione::class` across tests/ before adding any new mandatory wizard field.

## 2026-07-13 - US-003
- Wired the persistence of `manuale_letto_confermato_at`/`manuale_letto_torre_id` to the new step-1 confirmation flow instead of the removed torre-scoped one. `PrenotazioneResource::torreManualeRiferimento()` changed from `private` to `public static` so `CreatePrenotazione::mutateFormDataBeforeCreate()` can call it directly. In that method, unconditionally set `manuale_letto_confermato_at = now()` and `manuale_letto_torre_id = PrenotazioneResource::torreManualeRiferimento()?->id` — safe because `mutateFormDataBeforeCreate` only runs after the wizard's `accepted` validation rule on `manuale_step_confermato` (step 1) has already passed, so reaching this method implies the confirmation happened. `manuale_letto_torre_id` reflects the reference torre shown in step 1 (first active torre with a manual, by id), not whichever `torre_id` gets picked later in "Quando e dove" — matches the PRD's intent that they're decoupled.
- Files changed:
  - `app/Filament/Sezione/Resources/PrenotazioneResource.php` (`torreManualeRiferimento()` visibility only)
  - `app/Filament/Sezione/Resources/PrenotazioneResource/Pages/CreatePrenotazione.php` (`mutateFormDataBeforeCreate`)
  - `tests/Feature/Sezione/PrenotazioneManualeLettoTest.php` (one assertion updated: `manuale_letto_confermato_at` is no longer expected to be null after a successful create, now that persistence is wired — full rewrite of this file per PRD stays scoped to US-004)
- **Learnings for future iterations:**
  - No test in this repo yet exercises the case where the reference torre (step 1's manual) differs from the eventually-chosen `torre_id` — the only `Torre::factory()` used in the current manuale tests has `manuale_pdf_path === null` by default (see `database/factories/TorreFactory.php`), so `torreManualeRiferimento()` returns null in those scenarios too.
