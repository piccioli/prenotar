## Codebase Patterns
- Wizard steps for the /sezione Prenotazione resource live in `PrenotazioneResource::wizardSteps()` (app/Filament/Sezione/Resources/PrenotazioneResource.php); the outer `Wizard::make(...)` + nextAction()/skippable() config lives separately in `CreatePrenotazione::form()`, and both must be kept in sync when a step gates progression (nextAction's `->disabled()` closure receives `Forms\Get $get` and is evaluated with the whole live form state, so a condition defined for one step's field also protects later steps for free).
- Custom-styled Filament fields (checkbox with link/warning, radio cards, etc.) use `->view('filament.sezione.forms.components.<name>')` + `->viewData([...])` pointing at a blade partial under `resources/views/filament/sezione/forms/components/`; see `manuale-istruzioni-step.blade.php` / `torre-radio-cards.blade.php` for the pattern (uses `<x-dynamic-component :component="$getFieldWrapperView()" :field="$field">`, `$getState()`, `$getStatePath()`, `x-filament::input.checkbox`).
- `Torre::manuale_pdf_path` sits on the default `public` disk; consumers build the URL manually with `asset('storage/'.$path)`, not `Storage::url()`.
- Feature tests that fill the CreatePrenotazione wizard via `Livewire::test(CreatePrenotazione::class)->fillForm([...])->call('create')` must also `->set('data.manuale_step_confermato', true)` (added in US-001) or they'll fail with a new `accepted` validation error — this affected two test files (`PrenotazioneManualeLettoTest.php`, `PrenotazioneTipoMezzoValidationTest.php`) that had nothing to do with the manuale feature. Grep `CreatePrenotazione::class` across tests/ before adding any new mandatory wizard field.

## 2026-07-13 - US-002
- Removed the torre-scoped manual-confirmation coupling from the "Quando e dove" wizard step, now that US-001's always-first "Manuale d'istruzioni" step owns the single mandatory confirmation. Simplified `CreatePrenotazione::form()`'s `$bloccaAvanzamento` to depend only on `manuale_step_confermato` (dropped the now-dead `$torreSenzaManualeConfermato` closure). Updated the Riepilogo step's "Manuale d'istruzioni" row to read `confermato` from `manuale_step_confermato` (the new step-1 field) instead of the removed `manuale_letto_confirm`, so the summary doesn't silently regress to always showing "non confermato". Deleted the now-unreferenced `manuale-checkbox.blade.php` partial.
- Files changed:
  - `app/Filament/Sezione/Resources/PrenotazioneResource.php`
  - `app/Filament/Sezione/Resources/PrenotazioneResource/Pages/CreatePrenotazione.php`
  - `resources/views/filament/sezione/forms/components/manuale-checkbox.blade.php` (deleted)
  - `tests/Feature/Sezione/PrenotazioneManualeLettoTest.php`
- **Learnings for future iterations:**
  - Important side-effect of this story: `manuale_letto_confermato_at` / `manuale_letto_torre_id` are now NEVER set on create (no field in the form writes them anymore) — they'll be `null` on every new Prenotazione until US-003 wires them up in the new step-1 flow (`torreManualeRiferimento()` + the `manuale_step_confermato` checkbox's confirmation). This is expected/transitional, not a regression to fix now.
  - `PrenotazioneManualeLettoTest.php` was trimmed to drop scenarios that tested the removed torre-scoped checkbox/reset behavior (kept: no-confirmation-blocks-regardless-of-torre, confirm+torre succeeds, confirm+no-torre succeeds). Full re-coverage per the PRD (manuale-not-available warning scenario, wizard step count title update) is explicitly scoped to US-004 — don't re-derive it early, US-003's persistence wiring needs to land first or those assertions (`manuale_letto_confermato_at` not null) would fail.
  - When removing a Filament field that's read via `Forms\Get $get(...)` in another step's closure (e.g. Riepilogo's `gruppiRiepilogo()`), grep the whole resource file for the field name before deleting — `$get()` on a removed/renamed field silently returns null rather than erroring, so a stale reference degrades UI behavior instead of failing loudly.
