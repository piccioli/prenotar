## Codebase Patterns
- `Filament\Support\Colors\Color::hex('#rrggbb')` generates a full 50–950 shade
  palette from a single brand hex via `Color::generateShades()`: shade 500 is
  exactly the input color, every other shade (including 600, the default Filament
  "primary" reference shade) is algorithmically lightened/darkened from it — don't
  expect the exact input hex to reappear verbatim at 600 in the rendered CSS
  variables, that is expected Filament behaviour, not a bug.
- `->viteTheme('resources/css/filament/{panel}/theme.css')` resolves through
  Laravel's own `Illuminate\Foundation\Vite` invokable against the **default**
  `public/build/manifest.json` unless a custom `buildDirectory` (2nd arg) is
  passed — and passing one requires actually configuring `laravel-vite-plugin`
  to emit a separate manifest under that subdirectory. With a single shared
  `vite.config.js` input array (all 3 panel `theme.css` entries in one build),
  omit the 2nd arg entirely; all 3 panels resolve fine against the one manifest
  Vite already produces.
- Tailwind's `@config 'path.js';` directive must come **after** all `@import`
  statements in the same CSS file (postcss-import enforces "@import must precede
  all other statements"), otherwise `vite build` throws a warning per malformed
  file. Order per theme entry: `@import` (Filament base + our tokens) first,
  then `@config`, then any panel-specific `:root {}` overrides.
- Font self-hosting (no external CDN calls at runtime): use an npm package like
  `@fontsource/<font>` and `@import '@fontsource/<font>/latin.css';` from a CSS
  file processed by Vite — Vite's CSS pipeline resolves the node_modules import,
  rewrites the internal relative `url()`s and copies the woff/woff2 files into
  `public/build/assets/` with hashed names automatically. No manual asset
  copying needed. The per-subset files (`latin.css`, not `400.css` which bundles
  every unicode range including cyrillic/greek/vietnamese) keep the bundle lean
  when only Italian/Latin content is needed.
- `./vendor/bin/sail npm install` / `sail npm run build` work fine even though
  `node_modules` doesn't exist yet on host — Sail's `laravel.test` container has
  its own Node/npm, no need to install anything on the host machine.
- Design token source-of-truth files live in `tasks/design-reference/*/tokens/*.css`
  but per that folder's own README they are "materiale di progettazione ...
  non renderizzabile standalone ... non va servito dall'app": don't `@import`
  them directly into a compiled bundle. Copy the values 1:1 into the app's own
  `resources/css/...` tree (with a comment noting the source of truth), so the
  design-reference folder is read-only reference material, never shipped.
